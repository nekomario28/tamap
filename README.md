# TaMap 🗺️

**タスクをつなぎ、未来を描く。**

TaMap（タマップ）は、**GrokBotの複数のAI Botがチームとして協力**し、プロジェクトのタスク分解・依存関係の整理・リスク分析・次のアクションの提案を行う、会話型のプロジェクト支援AIチームです。

**コンセプト：** プロジェクトの状況を伝えるだけで、AIチームが「全体像」と「次の一手」を整理する。

## 名前の由来

**TaMap = Task-aware Multi-Agent Planning**

- **Task-aware**：タスクとその関係性、進捗状況を理解する
- **Multi-Agent**：専門性の異なる複数のAIが協力する
- **Planning**：根拠に基づいて次の行動を計画する

「**Task + Map**（タスクの地図）」の意味も込めています。

## 解決したい課題

プロジェクトが複雑になると、タスク一覧だけでは以下が見えづらくなります。

- 何が終わらないと次へ進めないのか
- どのタスクの遅延が全体に影響するのか
- 今、何を優先すべきか

TaMapは、こうした情報を**複数の専門Botで分担して整理・検証**します。

## 主な機能（MVPの目標）

1. **Task Mapping** — プロジェクトをタスクに分解し、依存関係を表・図で整理する
2. **Bottleneck Analysis** — 後続タスクへの影響が大きい箇所や進行上の障害を見つける
3. **What-if Simulation** — 「このタスクが遅れたら？」に対し、影響を受ける後続タスクを特定する
4. **Action Planning** — 分析結果を統合し、今取り組むべき行動を3つ提案する
5. **Quality Check** — タスクID、依存関係、分析結果の矛盾を確認する

※ タスクの所要時間など、入力されていない数値は推定値として断定しません。

## AIチーム構成

| Bot | 役割 | 主なアウトプット |
| --- | --- | --- |
| **TaMap PM** | ユーザーの依頼受付、タスクの振り分け、最終結果の統合 | プロジェクト要約・優先アクション |
| **Map Architect** | タスク分解と依存関係の整理 | タスク一覧・依存関係マップ |
| **Risk Analyst** | ボトルネック検出と遅延影響分析 | リスク・影響範囲・対応案 |
| **Quality Reviewer** | 矛盾・漏れ・根拠の確認 | レビュー結果・修正提案 |

### 分担フロー

ユーザー → TaMap PM → Map Architect → Risk Analyst → Quality Reviewer → TaMap PM → 最終提案

各Botは担当範囲の分析に集中し、確認できない情報は「未確認」または「仮定」として明示します。

## 使い方

1. GrokBot上で4つの役割を持つBotを用意し、上記の担当内容を指示として設定します。
2. Bot同士が分析結果を受け渡せるよう、利用環境に合わせてチームの会話・連携を設定します。
3. **TaMap PM** にプロジェクト概要やタスク状況を送ります。
4. タスクマップ・リスク分析・品質レビューを受けて、最終提案を確認します。
5. 「特定のタスクが遅れたら？」と追加で質問し、計画を再評価します。

### 入力例

**プロジェクト：タスク管理アプリ開発**

- T1 要件整理：完了、依存なし
- T2 UI設計：完了、T1に依存
- T3 DB設計：進行中、T1に依存
- T4 API実装：未着手、T3に依存
- T5 画面実装：進行中、T2に依存
- T6 統合テスト：未着手、T4とT5に依存
- T7 リリース：未着手、T6に依存

**質問：** 依存関係とボトルネックを整理し、T4が遅延した場合の影響範囲と、次に取るべき3つのアクションを教えてください。

### 出力イメージ

**依存関係：** T3 → T4 → T6 → T7

**遅延シミュレーション：** T4の遅延はT6・T7に波及する可能性があります。

**優先アクション：**

1. T3（DB設計）を完了させる
2. T4（API実装）の着手条件を確認する
3. T6（統合テスト）の準備を先行する

※ 上記は想定例であり、実際のBot実行結果ではありません。

## ハッカソンでの検証ポイント

- [ ] 4体のBotが役割に沿って結果を引き継げる
- [ ] 依存関係に存在しないタスクIDや循環がない
- [ ] 遅延したタスクから後続への影響を正しく追跡できる
- [ ] Quality Reviewerの確認内容が最終回答に反映される
- [ ] 追加質問で優先アクションが更新される
- [ ] 90秒以内のデモで一連の価値を説明できる

## 開発方針

**4時間のハッカソン向けMVP**として、Webアプリや外部DBの開発よりも、**GrokBotチームの役割設計・連携・分析品質**に集中します。
